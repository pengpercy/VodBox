# 内置 EPG · 直播增量设计

> 2026-10-11 · 当前选定规格。仅设计，不含生产实现。依据现有 LiveView / LiveViewModel 与 `.alma/epg-research-20261011/handoff-report.md`；实测是日期快照，不代表持续可用性承诺。

## 1. 已选方案与边界

保留当前「频道卡片网格 + 分组下拉 + 搜索 + 独立播放窗口」，不重做直播页、不加内嵌播放器、不改卡片点击播放语义。

- 每张频道卡片沿用现有 EpgNow 所在行，只显示一行当前节目或简短状态。
- 页面底部增加选中频道的紧凑节目摘要，显示当前 / 下一节目；「展开节目表」展开同一区域的纵向单频道节目单。
- EPG 首次使用自动获取内置源，无需填写地址。默认 112114，自动以 51zmt 主源补充可信匹配且主源当前缺失的频道；不合并所有八源。
- 设置沿用现有「源与订阅」中的节目订阅入口，支持手动订阅覆盖与恢复内置；手动失败保留旧数据，不偷偷改回内置。
- 所有 EPG 加载、刷新、过期与错误均独立于直播播放状态；不会触发重新播放、自动切台或换线。
- 节目单是播出信息，不是回看入口；过去节目不提供点击播放、seek、回看按钮或可回看承诺。

## 2. 现状优先于旧原型

`LiveView.axaml` 实际只有紧凑工具栏和频道网格；`ChannelCardRows` 经 ListBox + VirtualizingStackPanel 做行虚拟化，内层 UniformGrid 每行固定 194 DIP。卡片台标区 128 DIP、频道名 14、EPG 行 11，现有点击进入独立播放窗口。

`LiveViewModel` 已有 CurrentChannel、EpgNow/EpgNext、EpgTimeline、订阅下载 / gzip 导入 / 缓存与取消代次保护，但没有内置源、周期自动刷新、全频道当前节目的可靠更新，也没有完整频道声明和源命名空间。EpgNext / EpgTimeline 目前未绑定到主页面。

`design/DESIGN.md` 直播三列、内嵌播放、横向回看时间轴是旧方向，不作为本次布局依据；保留其 Fluent、主题资源、圆角和紧凑层级风格。

## 3. 页面与交互

工具栏不新增常驻源选择器，仅在「共 N 个频道」旁放紧凑「节目表」状态入口；正常显示「内置节目表」，异常显示短状态。点击定位设置中的节目表区。

卡片 EPG 行固定预留一行，当前节目标题单行省略，不放下一节目、时间范围、进度条、刷新按钮。悬停提示可包含完整频道名、节目时间和节目标题；不可仅靠 hover 提供必要状态。

点击卡片保持播放行为，同时使底部摘要跟随 CurrentChannel。摘要未选频道时不占位；频道锁定或清空时同步隐藏。摘要与节目单切换不调用播放器。

底部摘要约 88–104 DIP：频道名 + 当前节目时间/标题 + 下一节目开始时间/标题 +「展开节目表」。展开后变为同一底部区域，含摘要、日期选择、状态、虚拟化纵向节目行，默认今日定位当前节目；收起恢复摘要。节目表高度上限为可用内容区 45%，优先保留至少一行频道卡片可见。窄窗口允许摘要两行排列，不挤压现有搜索控件。

节目行显示本地时间范围、标题与「正在播出 / 已结束」文字，当前节目用 `CardHoverBrush` 轻背景和明确文字标识，其余中性；不显示海报、节目分类等非必要信息。只提供实际有数据的日期与今日，不臆造未来七天内容。跨午夜标注日期。本次不增加进度条，避免与播放器进度或回看能力混淆。

## 4. 必须区分的状态

- **加载**：首次无缓存「正在加载节目表…」；频道仍可点击播放，EPG 行静态占位，不把整个频道页换为骨架屏。
- **无匹配**：已有可用频道目录但无法映射时，卡片「未匹配节目表」，详情解释可在设置修正匹配；歧义为「频道匹配待确认」，不任取第一项。
- **无节目**：已匹配但频道没有节目记录时「暂无节目安排」。有将来记录但当前空档显示「当前暂无节目」，下一节目照实显示。
- **过期**：已匹配、存在历史记录且最后有效结束时间不晚于现在，卡片「节目表已过期」；历史节目可读，但不能标作正在播出。
- **错误**：获取 / 解压 / 解析 / 超限失败且无可用缓存时「节目表加载失败」；详情提供「重试」「节目表设置」。有仍有效缓存时保留真实节目，详情标注「更新失败，使用缓存」。
- **后台更新**：保留已有节目，只有状态入口显示「正在更新…」；不使每张卡片闪动或跳高。

源网络健康、数据新鲜度和频道匹配是独立维度；错误不冒充无匹配，过期不冒充无节目。

## 5. 数据源决定

112114 在 2026-10-11 当天覆盖 540/540 唯一频道，18,725 条原始节目；采样现在覆盖 529/540，故不能承诺每个频道当前都有节目。51zmt 主源当天和现在均 100/100，3,869 条节目，轻量、可补充核心频道。

epgpw_cn 镜像当天仅 121/710 且滞后，不适合默认。erw 超过现有字符与节目数限制，TW 超过字符限制，不能默认为直接可导入。51zmte1/e2、HK 本次不进入自动下载组合，避免增加体积、名称歧义和源级时区复杂度。

内置来源必须按源保存 (sourceId, channelId)，不能拼接 XML 后按数字 id 全局匹配。优先当前来源明确的 tvg-id；其次经过审阅的唯一名称 / 别名。保留 +、4K/8K、地区和国际版本差异；不全局去掉 HD、台、频道等。不同源不能拼成看似完整的连续时间表，单频道一次只采用一个可信来源。

手动订阅保存成功后覆盖内置来源的展示，不与内置自动混合；清除覆盖或「恢复内置节目表」才恢复内置。错误保留旧有效缓存；来源切换必须在新候选数据验证后原子提交。

## 6. 性能与后台刷新契约

继续有限视口的频道行虚拟化，EPG 只更新行内数据，不重建 ChannelCards / ChannelCardRows，不改排序、筛选、选中态或滚动位置。节目单同样虚拟化，无嵌套无限高度 ScrollViewer。

后台下载 / 解压 / 解析 / 去重 / 建索引；按来源和频道建立有序节目索引，不每 30 秒为每个频道扫描全节目。滚动期间只刷新可见卡片必要文案，摘要及展开节目单优先；画面稳定后补齐。

首次打开直播立即读缓存并发起内置刷新；之后每 2 小时检查，恢复前台时若距离上次成功超过 2 小时则更新。相同源请求去重，切源 / 退出取消并阻止旧结果覆盖。后台失败不弹模态、不写播放错误状态，提供退避与手动重试。

UI 将「最近成功获取」与「数据覆盖日期」分开，不能用 HTTP Date、gzip mtime 或仓库 last_update 冒充上游更新时间。频道时效按本频道实际节目区间判断。
